    What you are playing

    The server runs the competition file, agent.py, unchanged behind a small HTTP endpoint: a position goes in as FEN and a move comes back. Its board, move generator, evaluation and search are compiled by Numba when the server starts. The search is negamax with alpha-beta, iterative deepening, aspiration windows, a transposition table, principal variation search, null-move pruning, late move reductions, static exchange evaluation and more, all listed in the repo's build notes.

    This is not its tournament strength

    • Rated games gave it 120 s + 0.5 s a game on one core, and a slowest move of a few seconds. Here it gets at most 0.5 s a move on a small shared container.
    • Requests are stateless. Every move starts a fresh search with an empty transposition table and no memory of earlier positions, so it cannot see repetitions from earlier in your game. The page enforces the draw rules itself.
    • The server sleeps when idle to save cost, so the first move after a quiet spell waits while the search compiles again.
